# 存档可写性检查清单（拿到存档后按这个逐项验）

| # | 检查 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | 容器格式 | 读文件头/魔数/压缩标志；拆记录表 | 能列出记录/字段，不是整体加密 |
| 2 | 元件实体记录 | 找 prefab/资源路径/名称 → 对应实体节点 | 能找到每个元件的实例节点 |
| 3 | 坐标字段 | 对照「原始 vs 手动摆好」两份存档 diff | 找到 ±位置/旋转/缩放 的数值字段，且数量级合理（米/格） |
| 4 | 结构与原型 | 检查实体是否有 template/原型引用、ID 规则 | 只改数值即可，不需要新建未知结构 |
| 5 | 校验/哈希 | 搜文件尾部/记录尾部是否有 hash/checksum/签名；改一个坐标后看校验位 | 若无签名校验 → 可写；若有 → 需要同算法重算（再确认编辑器是否校验） |
| 6 | 引用完整性 | 实体 → 资产/模板引用是否闭合 | things 引用齐全、无悬空 |
| 7 | 回读一致性 | 写完重读、逐字段比对、四门禁（重读/往返/幂等/引用） | 全过 |
| 8 | 编辑器接受度 | 把写出的新档导入编辑器（你那边操作） | 能打开、元件在目标坐标、无报错（最关键一环） |

## 决策

- 1–7 全过、8 通过 → **可写**：`save_scene_place` 上云端，纯 Node 跑。
- 1–7 过、8 失败 → 存档有隐藏约束：退回「插件出坐标清单」的人工路径，或改走编辑器自动化（GUI）。
- 1–4 任一项过不了（加密/不可解析）→ **不可写**：只做坐标清单。
