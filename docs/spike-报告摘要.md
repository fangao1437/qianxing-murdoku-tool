## 1. 结论（对照旧路线）

| 问题 | 旧（Ayaya，GPL-3.0） | 现在（genshin-ts，MIT） |
| --- | --- | --- |
| 节点图能由代码生成吗 | 能 | **能** `[实测]` |
| 生成的图能被工具链接受吗 | 能（外部 `validate-file`） | **能** `[实测]`（`gsts` 编译出 `.gia`） |
| 能落盘进 `.gil` 吗 | UNKNOWN（要外部导出工具） | **能** `[实测]`——产出**真实被注入的 `.gil` 副本**（§3） |
| 能被游戏/编辑器接受吗 | UNKNOWN | **UNKNOWN（真机未验证）** |
| 节点名→参数/端口表 | 能（558/534） | **能，且更大**：729 节点 / 620 中文名 |
| 许可 | GPL-3.0（只能子进程隔离） | **MIT**（可入库、可分发、可 import） |

一句话：**"生成 → 编译 → 注入 `.gil`"全链路跑通、可复现、有回归；唯一还缺真机。**

## 2. 为什么以 genshin-ts 为主（以及代价）

**选它的理由**

| 维度 | genshin-ts | Ayaya_Miliastra_Editor |
| --- | --- | --- |
| 语言同构 | TypeScript/npm，产物是**人可读、可手改**的 TS 源码 | Python 栈，只能"生成 `.py` 字符串 + 起子进程" |
| 许可 | **MIT** ⇒ 数据可入库、代码可直接 import、可随发布物分发 | GPL-3.0 ⇒ 只能子进程隔离、派生数据不敢入库 |
| 构建 | 单包 + node，本机无系统 Python 也能跑 | 需 Python 3.10–3.12 + 几万文件仓库副本 |
| 完善度 | 官方文档站、模板、ESLint 规则、注入安全校验 + 自动备份、`gsts maps`、可导出 IR JSON | 逆向工具集，能力更全但没有编译期语义层 |
| 对 AI 友好 | `definitions/*.d.ts` 有完整类型 + 中文 JSDoc ⇒ 可直接抽成机读目录（`nodes.json` 的来源） | 端口名只在 Python 的 `@node_spec` 里，要静态解析 |

**代价（诚实列出）**

1. **必须锁版本**：上游迭代快（本轮 `0.2.3`）。升级要重跑 `gen-nodes` + `run-tests` 并 diff `data/nodes.json`。
2. **包装层不薄**：依赖 16 个包（含 `protobufjs` / `esbuild` / `typescript`），首次安装要联网拉 ~55 个 tarball（本机约 3 分钟）。
3. **注入受安全规则约束**：目标图必须已存在且（空 or `_GSTS*`），否则要显式 `skipSafeCheck`。
4. **注入后必须重载地图**：这是流程纪律，代码层面兜不住。
5. **节点命名有漂移**：109/498 服务端节点拿不到中文名/方法名（`emit` 直接拒绝生成这批）。

## 3. 安装 / 编译 / 注入 的真实产物（`[实测]`）

**安装**：`genshin-ts@0.2.3`（MIT，`bin: gsts → bin/gsts.mjs`），`+55` 包，**需要联网**。
`pnpm install` 退出码 **1**（`[ERR_PNPM_IGNORED_BUILDS] … esbuild@0.28.2, protobufjs@7.6.6`）——
**不影响使用**（esbuild 二进制在可选平台包里），实测编译/注入全通。`gsts` 启动还会打两条
`update check failed / notice check failed`（到 GitHub 超时），**只是 warning**。`gts-build.mjs` 已过滤。

**compile**（`gsts -c gsts.config.ts --noinject --lang zh-CN`）产物：

| 文件 | 量级 | 说明 |
| --- | --- | --- |
| `<name>.gs.ts` | 三百多字节 | 展开后的节点调用 |
| `<name>.json` | 五百多字节 | IR |
| `<name>.gia` | **360–700 B**（最小闭环） | 可注入产物 |

**inject**（`injectGilFile()`，对副本操作）产物：

| 文件 | 字节 | sha256 前 16 |
| --- | --- | --- |
| 源 `.gil`（**只读**） | 1 699 178 | `714c6e9764483ea5…` |
| `<base>.before.gil`（逐字节副本，注入基线） | 1 699 178 | `714c6e9764483ea5…` |
| `<base>.after.gil`（**真的被注入过**） | 1 698 825 | `834d1637d841dfd6…` |

前后字节差 **−353**；源存档 sha256 前后一致 ⇒ **仓库里的存档一个字节没动**。

**读回对账** `[实测]`（用上游解码件解目标图 id `1073741825` / `type 20000`）：

```
before: nodeCount=7  nodes=[1610612746,1610612750,22,652,77,248,128]   ← 被替换掉的旧图内容
after : nodeCount=3  nodes=[71,1,22]
```

`71` = `whenEntityIsCreated`（实体创建时）、`1` = `printString`（打印字符串）、
`22` = `setCustomVariable`（设置自定义变量）—— 与 `specs/min-loop.json` 的 1 触发器 + 2 节点**逐个对上**，
图 id / 图类型不变。这三个 id 与本仓库 `data/nodes.json` 里 `实体创建时.id=71`、`打印字符串.id=1`、
`设置自定义变量.id=22` **同一口径**（可交叉验证）。

> 顺带修正一条旧结论：**这些存档里本来就有服务端节点图**（`id=1073741825`、`type=20000`）。
> 旧报告里"我们这些档没有节点图"是**假阴性** —— 启发式把控件 ID 命名空间和 graph id 混在一起了。

## 4. 注入的三条规则（全部实测）

| 规则 | 实测表现 |
| --- | --- |
| 目标图**必须存在**，且（空图 or 名字以 `_GSTS` 开头） | 不加开关被拒：`[error] target NodeGraph not empty and name not _GSTS*: 新建节点图`（那张旧图有 7 个节点、名字叫"新建节点图"） |
| `inject.skipSafeCheck`（= `skipNonEmptyCheck: true`）可关掉这条检查 | 加了之后 `mode=replace` 成功 |
| **注入后需要重载地图** | ⏳ 只能真机验证；代码层面无法证伪 |

注入的两条路（都实测）：

- **路 A：`gsts` 配置注入**（上游官方口径）：只认
  `%LocalLow%\miHoYo\原神\BeyondLocal\<playerId>\Beyond_Local_Save_Level\<mapId>\<mapId>.gil`，
  **不接受任意路径**，但注入前会自动备份；`gsts maps` 能列出本机真实存在的地图。
- **路 B：直接调 `injectGilFile()`**（本仓库 `gts-build.mjs` 采用）：可指定 `outPath`、可只对**副本**操作，
  不碰真机存档目录。

> 本仓库刻意只实现路 B，并且**只写 `--outdir` 里的副本**。

## 5. 风险矩阵（本轮实测）

| # | 风险 | 真实表现 | 缓解 |
| --- | --- | --- | --- |
| 1 | 许可 | gts + 其内嵌数据包**都是 MIT** ⇒ 派生表可入库 | `_provenance` 写死 upstream/license/sources/regenerate；测试断言 MIT |
| 2 | 版本漂移 | 上游发版快，定义文件一改 `nodes.json`/`emit` 可能漂 | 锁 `0.2.3`；升级必须重跑 `gen-nodes` + `run-tests` 并 diff |
| 3 | 构建/环境 | `install` 退出码 1（IGNORED_BUILDS）但功能正常；`gsts` 两条网络告警 | 允许 IGNORED_BUILDS；告警当噪声过滤 |
| 4 | 网络 | npm registry 通；`raw.githubusercontent.com` 超时 | 只用 npm registry；反代备用 |
| 5 | 注入依赖地图与信号表 | 编译期会从目标地图抽信号定义到 `src/resources/signals.ts` | 先在编辑器里建图并保存，再注入；`gsts maps` 找 `mapId` |
| 6 | 注入后需重载地图 | 未重载就用编辑器保存 ⇒ 注入内容被覆盖 | 交付文档写死这条；`gts.config` 的 `reinjectOnMapChange` 可兜底 |
| 7 | 安全规则 vs 旧档 | 旧档里的图叫"新建节点图"（非空、非 `_GSTS*`）⇒ 默认注入被拒 | 正路：建 `_GSTS*` 图；临时路：`--skip-safe-check` |
| 8 | 节点命名漂移 | 109/498 拿不到中文名/方法名 | **不猜**：`method` 为空就拒绝生成并报错 |
| 9 | 真机 | 完全未验证 | 见 §6 |

## 6. 真机未验证点（必须说清，不许当已验证）

1. **注入后的 `.gil` 能不能被编辑器/游戏吃下** —— 文件层已经写进去了（图 id/类型/节点数都能对账），
   但"编辑器打开看不看得见这张图、能不能编辑"**没验证**。
2. **`genericId` 与节点语义的对应**只从数据包/官方命名推出来的，**没有在编辑器里逐个比对**。
3. **运行期效果**：`实体创建时 → 打印字符串 → 设置自定义变量` 是否真的写进了自定义变量，未验证。
4. **信号/自定义变量/资源**：`signals.ts` 的抽取逻辑只在真实地图上才触发，本轮**只读代码，未执行**。
5. **"注入后重载地图"** 这条规则只在文档里看到，**没有在客户端上跑一遍**。
6. **本工具产出的 `.gia` 手动导入**：上游还有"直接把 `.gia` 当资产导入"的路子，
   `.gia` 作为**资产类型**在真机上导入成功过（主项目控件侧），但**本工具链产出的 `.gia`** 没导入过。

## 7. "节点图交付"解除阻塞还差什么

**已经不缺**：写入器（有，MIT）、节点表（有，MIT）、生成器（有）、编译（通）、注入（通）、离线回归（72 项）。

| # | 缺什么 | 谁做 | 说明 |
| --- | --- | --- | --- |
| 1 | **一次真机确认** | 用户 | 把 `after.gil` 导进编辑器 → 看 id `1073741825` 的图是不是 3 个节点 → 关卡跑一次看变量有没有被写 |
| 2 | **一个 `_GSTS*` 命名的空图** | 用户（编辑器里点几下） | 有它就不用 `skipSafeCheck`，走完全干净的安全路径 |
| 3 | **把 `.gia` 手动导入验证一遍** | 用户 | 交叉验证"是注入坏了还是我们生成的图坏了" |
| 4 | 补齐 109 个命名漂移节点 | 我们 / 上游 | 等上游修，或按 `reflect_map`/节点 id 反查，**不许猜** |
| 5 | 端口语义名 ↔ pin 索引对齐 | 我们 | 没有它就只能生成"结构骨架"而不是"等价图" |
