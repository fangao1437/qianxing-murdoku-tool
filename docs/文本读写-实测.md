## 一 ★★★ 文本在记录里的位置

```
<记录>
 └─ #505 → #503 → #75            = 【文本属性组】（每条记录只有一个 ✓）
      ├─ #501  颜色（varint，例 20）
      ├─ #504  字色 ARGB（varint，例 0xFF827C6D = 4286749805）
      ├─ #505 / #507   遮罩色 / 描边阴影
      ├─ #508 / #509   水平 / 垂直对齐（1 = Center）
      ├─ #510  文本本体 → #501 = UTF-8 字符串（wt=2 叶子）★
      ├─ #512 / #513   fontSize / minimumFontSize
      └─ （状态块里的 #505 对）位置 / 尺寸 —— 稀疏编码，0 分量不写
```

★★ **两个坑** ✗：
1. ★ **`#510` 在 `#85`（图像块）里是【拉伸开关】（varint）** ✗ —— ★ 同号字段不同义 ✓
2. ★★ **空文本时 `#510` 是空消息（`wt=2 / len=0 / 无子`）** ✓
   ⇒ ★ **写文本必须复用它** ✓ —— ★ 再 push 一个 `#510` 会出现两个同号字段，引擎取哪个不确定 ✗

## 三 ★ 写法（伪代码）

```js
// 1) 找组：记录 → #505 → #503 → #75（严格唯一）
const grp = nodesAt(rec.field.sub, [505, 503, 75])[0];

// 2) 复用已有 #510（空的话是 wt2/len0/无子）
let p510 = grp.sub.find((f) => f.field === 510);
if (!p510) { p510 = { field: 510, wt: 2, sub: [], payload: Buffer.alloc(0), len: 0, isText: false }; grp.sub.push(p510); }
if (p510.sub == null) p510.sub = [];
p510.payload = Buffer.alloc(0); p510.len = 0; p510.isText = false;

// 3) 写 #501 = UTF-8
const buf = Buffer.from(text, 'utf8');
let leaf = p510.sub.find((f) => f.field === 501 && f.wt === 2);
if (!leaf) { leaf = { field: 501, wt: 2, payload: buf, len: buf.length, isText: true, sub: null }; p510.sub.unshift(leaf); }
else { leaf.payload = buf; leaf.len = buf.length; leaf.isText = true; }

// 4) 字号 / 字色（可选）
setNum(grp, 512, fontSize);      // 或 513
setNum(grp, 504, argbColor);     // 如 0xFF827C6D
```

★ **文本里的换行** ✓：★ 存的是 `\n` ✓（导出成清单时写成 `<br>` ✓）

## 四 ★★ 「写了却看不见」的真实原因

★★ **不是存储问题** ✓ —— ★ **是文本框太小** ✗：
- ★ 高度 < 2×字号 ⇒ 引擎不画 ✓
- ★ 窄框宽度 < 1.5×字号 ⇒ 引擎不画 ✓

⇒ ★ 修法 ✓：`_fix_tutorial_text_metrics.mjs` —— ★ **最小高 = 2×字号、最小宽 = 1.5×字号、中心不动** ✓
