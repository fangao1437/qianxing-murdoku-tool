# 限制清单（已知缺口 + 真机验证清单）

> 这份文件的作用：**让下一个人不用重新发现这些坑**，也让"已完成/未完成"没得含糊。
> 口径：2026-10，`genshin-ts@0.2.3`，节点表 729 条。

---

## 1. 一句话

**写方向的代码链路是通的、可复现的；"被游戏接受"这件事一次都没验过。**
读方向只有**控件层**是自足的，**节点图层**要外部 GPL 解码器，而 `.gia` 的节点图层解码还没接。

## 2. 数值缺口（每个都能在 `data/nodes.json` 里查到）

| 缺口 | 数字 | 表现 | 处置（已写死，别放宽） |
| --- | --- | --- | --- |
| 服务端节点**方法名漂移** | **109 / 498** | `nodes[].method` 为空（英文显示名与 TS 方法名对不上） | `emit.mjs` **拒绝生成**该节点并 `exit 2`，报错原文含"没有 TS 方法名…不能生成 gts 源码"。**不做模糊匹配、不做拼音/同义词猜测** |
| **缺中文端口名** | **321 / 498** 个节点（部分端口 `name: null`） | 只能位置参数；对象形式 `args` 会报"端口名对不上" | 用数组 `args`；要按名字写就必须先手工确认端口表 |
| 客户端节点端口名 | 客户端 231 个节点普遍 `inputs[].name = null` | 客户端图只能靠位置参数 + 已知签名 | 同上；客户端图的 `graph_subtype` 还必须手填（如 `bool_filter`） |
| **分支 / 循环** | 样本里出现 29 次（`双分支`） | 顺序调用模型表达不了控制流 ⇒ `CONTROL_FLOW_NODE` | **拒绝生成**；`--treat-branch-as-linear` 可降级为警告，但**语义不等价**且默认关闭 |
| **枚举 / 列表 / 字典常量** | — | `ENUM_CONSTANT` / `LIST_CONSTANT` / `DICT_CONSTANT` | **拒绝生成**（gts 的枚举成员/列表字面量写法未验证，字典布局未解） |
| **多出参属性名** | 覆盖度报告 §3 列了 28 处 | 取第 N 个出参要知道属性名 ⇒ `MULTI_OUT_PIN` | 只有 `data/node-aliases.json` 的 `out_fields` 登记过的才译得出 |
| **复合节点展开** | 5 份样本里 99 个定义 / 22 种类型 | **读得出**（名字/端口/连线/实现图 id），**译不出**（要展开实现图） | `COMPOSITE_NODE` **拒绝生成**；要么展开实现图（未做），要么当黑盒手写 |
| **`.gil` 的节点图段** | — | `giaread.mjs` 返回 `layout: 'other'` + `graphs: []` | 明说读不出来；`.gia` 才走原生解码 |
| 泛型重载 | 每节点 `reflect_map` 可用但未接入 | `R<T>` 之类泛型实参在数据包里是不同 pin | emit **还没用** `reflect_map` 挑重载 ⇒ 复杂泛型节点可能需要手写 `method`/参数 |
| 隐藏/派生 pin | 真实例：`设置自定义变量` 有 5 个输入但只传 4 个位置参数 | `inputs_types` 顺序不等于方法签名顺序 | 位置参数顺序以 gts 的 `definitions/*.d.ts` 方法签名为准 |

**为什么要写死这些**：这几种情况下"猜一个名字让它编译过"，产物会**静默错语义**——
编译能过、注入能过、游戏里行为是错的。那比报错更贵。所以 `read2spec.mjs` 用 `BLOCKERS` 分类拒绝，
退出码 2，并在 `translate.json` 里逐条写清"哪里拒了、为什么"。

## 3. 真机验证清单（**未做**，谁做都要按这个来）

下列每一步都标了"看到什么算过、看不到怎么归因"。样本 = `specs/min-loop.json` 那条最小闭环。

### 3.1 注入后的 `.gil` 被编辑器接受

1. 生成：`node src/emit.mjs --spec=specs/min-loop.json` → 得到 TS；
2. 编译+注入：`node src/gts-build.mjs --src=out/<name>.ts --workbench=<工作台> --copy-gil=<某>.gil --outdir=out/injected --skip-safe-check`；
3. 把 `out/injected/<base>.after.gil` **导进**编辑器（按你的常规导入方式）；
4. **过**：能在编辑器里打开这张图、看到 **3 个节点**（实体创建时 / 打印字符串 / 设置自定义变量），图 id 仍是注入前那个；
5. **不过**：
   - 图**不见了** ⇒ 注入写到了错误位置或存档结构不符（先怀疑"目标图不存在"那条规则没满足）；
   - 图**还在但内容是旧的** ⇒ 你**没有重载地图**就保存了（见 §4 第 1 条）；
   - 编辑器报**校验错误** ⇒ 记下原文，这是最有价值的证据。

### 3.2 运行期真的写进了自定义变量

1. 用注入后的档进关卡，触发"实体创建时"；
2. **过**：自定义变量 `qx_min_loop_flag` 变成 `1`（或在图上打印出了 `qx-min-loop: entity created`）；
3. **不过**：先确认脚本/图有没有挂上（`docs/读取与翻译算法.md` §6 里那条"端口语义名未对齐"可能让图结构对而语义错）。

### 3.3 本工具产出的 `.gia` 手动导入

1. 把 `dist/src/<name>.gia` 当**资产**导入千星沙箱；
2. **过**：资产出现在资产列表里、能拖进地图、图结构正确；
3. 说明：`.gia` **作为资产类型**导入在真机上成功过（主项目控件侧），但**本工具链产出的 `.gia`** 没验过，
   所以这条**不能**引用别人的成功来当自己的证据。

### 3.4 干净安全路径（不用 `--skip-safe-check`）

1. 在编辑器里建一张**名字以 `_GSTS` 开头**的空节点图，保存；
2. 用 `gsts maps`（或编辑器里看）确认它的 `mapId` / 节点图 id；
3. 用该 id 写 spec 注入，**不带** `--skip-safe-check`；
4. **过**：注入成功且 `mode` 不是 replace 的破坏性覆盖。
   这条路走通之后，`--skip-safe-check` 就只是排障开关，不是主路径。

## 4. 流程纪律（违反会造成"改了但没生效"）

1. **注入后必须重载地图**，再让编辑器保存。否则编辑器的内存态会把注入内容覆盖掉
   （存档回到旧内容，现象是"我明明注入了却没有"）。
2. **永不原地写存档**。`gts-build.mjs` 只接受 `--copy-gil`，产物落 `--outdir`；源文件 sha256 前后一致是自证。
3. **注入是替换整张图**（`mode=replace`）：目标图原有节点会被换掉。往有内容的图上注入前先确认这是你要的。
4. **许可证边界不松动**：`--target=ayaya` 的产物、`gen-ports --merge` 的结果都**不入库**。

## 5. 环境限制

| 项 | 说明 |
| --- | --- |
| Node | 实测 `v24.21.0`；`package.json` 写 `>=20`。零第三方依赖即可跑测试与 `emit` |
| Python | **只有** `--ayaya=`（外部 GPL 解码器）和 `--target=ayaya` 才需要（3.10–3.12）。主路线不需要 Python |
| 平台 | 本仓库的脚本在 Windows 上实测；路径处理用 `path`，没有硬编码盘符 |
| 网络 | 只有"装 genshin-ts"和"下载外部解码器"需要联网；**测试、emit、read 全离线** |
| 中文路径 | 全部命令都支持（调用时加引号即可）；仓库本身不含中文路径假设 |

## 6. 未验证的假设（写在这里，防止被当成结论）

- 注入 `mode=replace` 后编辑器保留 id/类型 —— 文件层对得上（`[实测]` 读回），**编辑器层没验**。
- `genericId` ↔ 节点语义的对应只从数据包推出，**没在编辑器里逐个比对**。
- `signals.ts` 抽取逻辑只在真实地图上触发，**本轮只读代码、未执行**。
- "注入后重载地图" 只在**文档**里看到，**没在客户端跑过**。
- 原生解码器是**用样本反推**的 wire 读法：5 份样本全过，但**样本之外的布局没验过**（`.gil` 就落在这一档）。
- 外部解码器的 `.gia` 入口（`parse_gia_to_graph_ir`）**没用过**；`.gia` 现在走我们自己的原生解码。

## 7. 想补缺口时的检查单

改任何一处之前，先跑这三条，别先改代码：

```bash
node test/run-tests.mjs                       # 必须仍是 通过 186，失败 0
node src/emit.mjs --spec=specs/min-loop.json  # 生成物 diff 应与之前一致（除非你就是要改它）
node src/coverage.mjs --in=<样本目录> --md=docs/official-gia-coverage.md   # 重算覆盖度（要样本 .gia）
node tools/sync-from-master.mjs --from=<主仓库>/tools/qx/graphcode        # 只在同步上游时用
```

- **升级 genshin-ts**：先 `gen-nodes --gts=`（重新生成 `data/nodes.json`）→ `run-tests` → **diff `data/nodes.json`**；
  条数变化（729/620/…）必须能解释，否则回滚。
- **给 `emit` 加节点能力**：只允许从 `data/nodes.json`（+ 人工核对过的 `data/node-aliases.json`）取事实；
  表里没有的**必须报错**，不许兜底猜。
- **给读方向加解码路径**：产物里必须写明证据来源（`[实测]` / `[推断]` / `UNKNOWN`），
  读不出来就写 `layout: 'other'` 这种**显式失败**，不许静默空结果。
- **别为了"让测试绿"放宽 `BLOCKERS`**：那些拒绝是产物语义的正确性闸门，不是障碍。
