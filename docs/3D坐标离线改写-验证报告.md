## 6 对上云方案意味着什么

- 这条路径**完全绕开 Blender / GIA / 账号权益**：纯 Node 解析 `.gil` → 改 `#11#1/#2/#3` 数值 → 写新档 → 重读校验；
- 所以它是「**云端坐标编排**」的正解：云端只做「读存档 → 按坐标表改 → 写新档 → 校验」；
- 边界（已验证范围）：**只改现有元件的变换字段**。新增/复制元件（要生成新实体记录、引用/ID 分配）尚未验证，那部分通常需要编辑器参与；
- 你的两种半自动形态里：
  - **A（你准备好所有元件，插件只调坐标）**：✅ 本报告已证明可行；
  - **B（插件按设计图把元件摆进去）**：元件先由你在编辑器放好占位，插件再按设计图算坐标覆盖 —— 也是同一套改数值逻辑，同样可行。

正好等于 `比对.gil` 的文件修改时间（21:33:25）。即：编辑器**只更新了保存时间，没有回滚/归一化任何坐标**。
