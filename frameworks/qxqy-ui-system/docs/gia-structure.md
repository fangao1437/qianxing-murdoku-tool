# 教程 GIA「翻页单击活动样式」结构解析

> 对象：`D:\新建文件夹\miHoYo Launcher\qianxing-murdoku\assets\教程UI系统_翻页单击活动样式.gia`（171,822 字节）
> 方法：自建 protobuf wire 解码器逐字段解析（`tools/pb.mjs` + 6 个探针脚本，见 §7）。
> 结论一句话：**它是一套"模板库/资产包"，不是可直接导入的界面存档**；可复用的是**角色构成（构建逻辑）**，不是字节。

| 段 | 内容 | 实测 |
|---|---|---|
| 头 | 5 个大端 u32 | `171818, 1, 806, 3, 171798` |

| 尾 | 4 字节 | `00 00 06 79` |

## 2. 顶层结构

`Root { repeated GraphUnit graph = 1; repeated GraphUnit accessories = 2; string filePath = 3; uint32 modeFlag = 4; string gameVersion = 5; }`

| `graph` (#1) | 4 | 2 个节点图单元 + **2 个界面** |
| `accessories` (#2) | 113 | 2 个节点图节点 + **111 条控件记录**（`which=15`） |
| 其余 | — | `#3` filePath、`#5` gameVersion（`#4` modeFlag 缺失） |

`graph` 四条：

| # | name | Id{class,type,id} | which | 判定 |
|---|---|---|---|---|
| 0 | `[玩家]教程节点图` | 5, –, 1073741825 | 9 | 服务端节点图容器 |
| 1 | `发送信号` | 23, –, 1073741826 | 14 | 节点图节点 |
| 2 | `[教程悬浮交互页]教程？教程！` | 1, 8, 1073741843 | 21 | **界面**（主交互页，37 个子引用） |
| 3 | `[教程悬浮交互页]教程角落` | 1, 8, 1073741929 | 61 | **界面**（角落挂件，3 个子记录） |

`accessories` 里的 111 条控件记录 = 这套样式用到的**全部控件与素材**（含模板实例与其子件）。

## 3. 控件记录的内部结构（已解出）

```
GraphUnit
├ #1  Id      { class=2, type=3, id=4 }        ← id 即该记录的 guid（与 id 段 1073741850+ 同域）
├ #2  relatedIds (repeated Id)                  ← 界面把「直接子控件」放这里
├ #3  name (string)
├ #5  which (int32)                             ← 单元种类
└ #19 UiControlGroup
    └ #1 ContentWrapper
        ├ #501 guid                            ← 记录自身 guid
        ├ #502 Info × n  {(a,b) 标签槽}
        │     (1,5)=guid   (2,6)=组内索引   (4,4)=相关 guid 列表   (6,55)/(39,55)=新版本槽
        ├ #503 children  ← **打包 varint 的 guid 列表**（多数记录用它表达子控件）
        ├ #504 parent    ← **父记录 guid（varint）**，界面根没有
        └ #505 Data × n  { #501=a, #502=b, #503=Details }
```

父/子的三套表达（必须都认，否则树会断）：

1. `content#504` parent —— 最准，控件记录普遍有；
2. `content#503` children —— 打包 varint，可整段解析成 `>1000` 的 guid 才算子列表（同 `.gil` 的 `#503` 双义陷阱）；
3. `Unit#2 relatedIds` —— **界面根**把直接子控件放这里（它的 `#503` 为空），且会把整棵子树的 guid 平铺进来。

## 4. Data 槽位 (a,b) —— 已知 + 未映射

| (a,b) | 出现次数 | 语义 | 依据 |
|---|---|---|---|
| `2/15` | 113 | **name** | Data#12 WrapperString{value=#501}；全记录都有 |
| `1/12` | 102 | **transform** | Details#13 Transform{ #12 MultiPlatform{ platforms[#501 platformType, #502 RectTransform{scale#501, anchorMin#502, anchorMax#503, offset#504, size#505, pivot#506, rot#508}} } } |
| `1/11` | 11 | **空 transform**（无 multiPlatform） | 同上但 `#12` 缺失，几何在别处 |
| `4/23` | 102 | **field14**（激活/初始隐藏/初始未激活） | Details#14 Field14{ #15 空串, #17 ClientInitialState{initiallyHidden=#503}, initiallyInactive=#502 } |
| `4/86` | 0（本文件） | 同上（控件族变体） | 插件 worker.js `br` 表 |
| `21/38` | 71 | **未映射**（新版本组件，每记录一条，最像"素材/图片组件"） | Details 内层 #31 |
| `38/56` | 16 | **未映射**（像"按钮/容器聚合组件"） | Details 内层 #46 |
| `27/43` | 11 | **模板引用槽**（值形如 `"教程2"` / `"教程5"`） | Details 内层 #37{ #501="教程N" }；对应旧 schema 的 `templateRefSlot` |
| `20/37` | 10 | 未映射（Details #30，含 f32 对，像 padding/尺寸组） | |
| `29/46,30/47,31/48,32/49,40/58` | 5 | 未映射（一组 5~6 个槽同时出现，像"页签列表"配置） | |
| `35/52,37/54,33/50,43/62,44/63,45/64` | 2 | 未映射（左右翻页按钮独有的一组，像"按钮四态 + 动效"） | |
| `9/25` | 4 | 未映射（值形如 `"{4:[教程模版_无需翻译]教程文案}"`，像分组/多语言键） | |
| `22/39` | 1 | 未映射（界面动效记录） | |

> ⚠️ 未映射槽位**不猜语义**。它们是 6.7.0 新增组件，模拟器插件内嵌 schema（覆盖到 Details#87）不认识，
> 因此本资产**不能无损往返**模拟器 GIA 链路。这也是"GIA 只作参考"的另一个理由。

**构建逻辑提炼（本框架照抄的部分）**：
1. 一屏之内：**页签条（跳页）+ 左右翻页（顺序翻页）+ 内容区（视窗）+ 关闭**；
2. 页签的"选中"用**两套素材互斥显隐**表达（官方没有 selected 态）；
3. 按钮的"悬停/按下/不可用"交给**编辑器四态**，脚本只管"能不能点"；
4. 页面切换**不重建控件**，只切显隐（容器不能藏，藏了就销毁）；
5. 与服务端的分工是**信号上行 + 变量下行**，客户端不写变量。

## 7. 解析工具（本仓库自建，可复用）

| 工具 | 用途 | 用法 |
|---|---|---|
| `tools/pb.mjs` | 最小 protobuf wire 读写器（varint/len/f32/fixed64；`decodeDeep` 自动尝试子消息） | 被其它脚本 import |

### 已知解析陷阱（都是实测踩到的）

1. **继承式重复**：界面根的 `relatedIds` 会把整棵子树平铺进来 ⇒ 按 `relatedIds` 反查"父"会得到**多父**假象，必须优先用 `#504`。
2. **`#503` 双义**：既可能是"打包 varint 子 guid 列表"，也可能是普通嵌套消息；判据是"能不能整段解析成合法 id 列表"（与 `.gil` 同款坑）。
3. **guid 跨桶撞号**：`graph` 与 `accessories` 各有 `1073741825` 等号段，建索引要分桶（本工具按 `acc` 桶优先）。
4. **pb.msg 语义**：本项目 `pb.mjs` 的 `msg(fs,n)` 返回的是**字段 n 的子节点数组**，不是节点对象 —— 早期脚本按"节点"用导致 `content.sub` 为空、树全断。
5. **中文编码**：改含中文的脚本**只能用编辑工具**，用 PowerShell `Get-Content|Set-Content` 会把 UTF-8 读成 GBK 再写回，直接把源码写坏（已发生过一次）。
