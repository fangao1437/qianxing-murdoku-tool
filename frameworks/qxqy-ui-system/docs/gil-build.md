> 目的：给「教程 UI 框架」（`lua/src/70_app.lua` 按名字发现控件的那套）造一个**能直接导入真编辑器**的
> 关卡存档 `.gil`，客户端 UI 里带齐 40 条界面控件 + 基础美术（可调色白模图片 + 文字），用来肉眼验渲染。

## 三、写一条记录要改哪几处

| 项 | 位置 | 备注 |
|---|---|---|
| **id** | ① 顶层 `#501` varint ② `#502 { #11 { #501 } }` ③ 每个 `#505` 槽 details 里的 `#504 { #2=1 #3=8 #4 }` | 实测一条记录**有 7~8 处**指向自己（图片因 `#84/#504` 多一处）⇒ **按"值 == 原型 id"全量替换**，只改第一处会让记录内部自称是原型 |
| **名字** | `#505(槽 2,15) / #12 / #501` UTF-8 字符串 | 原型上这个位置是**类型名**（"文本框"），实例上是实例名 |
| **父** | 顶层 `#504 = <parentId>` varint | 三个原型都没有 `#504` ⇒ **新建**；插入位置 = `#501/#502/[#503]` 之后（与 murdoku 记录同构）。图片供体自带 `#504=1073741888` ⇒ 改写 |
| **子列表** | 父记录**顶层** `#503`（payload 必须是纯 id 列表） | 原型没有 ⇒ `ensureChildListTop()` 新建（插在 `#502` 之后）；写 payload 后必须 `sub = null`（见坑 4） |
| **UI 根** | `/#9/#501` 顶层对象 id 表 | 骨架里 18 个（含画布默认容器节点 `1073742017`）⇒ 追加 `app.root` = 19 个。**根记录不进这张表，引擎/转换器都看不到它** |

### ★ `app.root` = **复用**基线里的画布默认容器节点 `1073742017`（不再新建顶层容器）

真机参照 `qianxing-murdoku/存档/470-遗留清理-v282.gil` 的形状：

```
1073741845 客户端控件容器  父=引擎占位 1073741825  子列表=0
1073741846 root           父=null  子=74  状态=4  pos 0  size≈0     ← 控件树全挂在它下面
```

即：**容器记录不挂孩子；画布根是一条父=null、带几何、带子列表的容器节点**。
骨架里正有这样一个 `1073742017`（`容器节点`、`parent=null`、在 `/#9/#501` 根表里、几何是整屏拉伸），
所以本工程**复用它当 `app.root`**（对它的 4 处改动，全部可从重读磁盘的 `.gil` 里看到）：

| 改什么 | 怎么做 | 重读证据（`--raw=1073742017`） |
|---|---|---|
| 名字 | 槽 (2,15)/`#12/#501` ← `"app.root"` | `记录 1073742017 name=app.root parent=null 状态=4 childList=[1073742040]` |
| transform | 把它的 transform 槽 `(1,12)` **原位替换**成从「容器节点」原型 `1073742022` 克隆的整槽（含 `#13/#12` 的 4 个平台块，槽内自引用 retarget 成 2017） | `#505(1,12) … #501{#502{#501{1,1,1} #502=f32(0),f32(0) #503=f32(1),f32(1) #504=f32(0),f32(0) #505=f32(0),f32(0) #506=0.5,0.5}}` |
| 几何 | 4 平台块双向拉伸：anchorMin(0,0)/anchorMax(1,1)/offset(0,0)/size(0,0)。**offset/size 写成显式浮点 0**（值是 0，但 `gilread.stateBlocks()` 要求尺寸对里有 2 个浮点才认状态块 ⇒ 这样才读回 `状态=4`） | 4 个状态包装，`状态=4` ✓ |
| 子列表 | `ensureChildListTop` 新建顶层 `#503` = `[1073742040]`（`screen.demo`）；并令 `screen.demo.#504 = 1073742017` | `#503 = <bin 5> d881808004` → `[1073742040]` |

`客户端控件容器 1073742016` 的子列表**保持 0**（与真机参照一致）；`/#9/#501` 根表**不追加**（2017 本来就在里面）。
⇒ Lua 端 `FindClientUIRoot("app.root")` 只查**根层**，所以 2017 必须真的叫 `app.root` 且**没有父**——这一步是「脚本能不能找到界面」的关键。

## 四、几何怎么写的

* 一条记录有 **4 套几何**（`KEYBOARD` / `TOUCHSCREEN` / `CONTROLLER_CONSOLE` / `CONTROLLER_MOBILE`），
  路径固定：`#505(槽 1,12) / #503 / #13 / #12 / #501×4`。
* ★ **层级比看上去深一层**：`#501` 是**状态包装**，里面才是 `#502 = 几何容器`；
  几何容器里 `#501{锚点组}`、`**#502 = anchorMin**`、`#503 = anchorMax`、`#504 = offset`、`#505 = size`、`#506 = pivot`。
  一开始我把 `pairOf(状态包装, 502)` 当 anchorMin，`setPair` 一写就把整块几何**抹平**了
  —— 症状是记录"状态=0"、几何槽从 327B 缩到 84B。**必须 `pairOf(几何容器, 502)`**。
* 零分量按引擎稀疏编码省略：`setPair(f,0,0)` ⇒ 该字段长度 0（空消息）。
  所以"整屏拉伸"容器（offset/size 全 0）读回来时**没有任何浮点**，
  `gilread.stateBlocks()` / `recs[].states` 会把它判成"状态=0"——这是读取侧的假象，不是没写。
  本次断言改用**结构定位**（按路径找 4 个状态包装，不看"有没有值"）。
* 锚点是 **float32**：`0.08` 读回来是 `0.07999999821186066` ⇒ 断言用 1e-4 容差。

## 五、文字 / 图片怎么写的

* 文字：`#505(槽 64,84)/#503 → #75(TextConfig) → #510 { #501 = "…" }`，字号是 TextConfig `#512`（varint）。
  原型的 `#510` 是**空消息**；写入后同时填 `sub`（编码以它为准）与 `payload`（只读工具看它）。
  其余 TextConfig 字段（字色 `#504`=白、对齐 `#507` 等）沿用原型默认。
* 图片：`#505(槽 73,96)/#503/#84` 里 **`#502` = imageColor（ARGB）**、**`#503` = assetId**。
  ★ 纠正一处仓库文档措辞：`docs/gil配图两条路.md` 把 `#84/#502` 叫 `imageSource`，实测它是**颜色**——
  同一个 `assetId=100001` 在供体里有 **7 种不同 `#502`**（白/绿/灰/…），murdoku 文档也写
  "`imageId=100001` + `imageColor` 调色"，`board.bg` 就是先例。本次**保留供体的 `#503`、只覆写 `#502`**。

## 六、层序（★ 唯一需要 Lead 拍板的点）

引擎语义（官方 + 真机双证据）是 **子列表越靠后 = 显示越靠上**：

* 官方《客户端控件API文档》`SetSiblingIndex`：「数值越大通常越靠后、**显示越靠上**」；
* `qianxing-murdoku/docs/底板选型与三个缺陷修正.md`：「`InstantiateClientUIControl` 建出来的控件**追加**在父级子列表**末尾** = 显示在**最上**」；
* 供体 `clue` 模板：`backrop1`（描边，在下）在子列表**第 1** 个，`backrop2`（填充，在上）第 2 个。

⇒ 为了得到"任务书列表里**先列出的在上层**"的观感，`build_gil.mjs` 默认（`--order=engine`）把
每个父的子列表写成**列出顺序的反向**（`plate` 在前、`text` 在后；`bg` 在前、`label` 在后；
`page.*` 整体压在最底）。**唯一例外是 `page.*`**：`70_app.lua` 规定"页顺序 = 同级顺序"，
所以页之间保持 `p1→p2→p3`（页同一时刻只显示一个，页间层序无影响）。

⚠️ 模拟器插件是**反过来的**（`gil_to_save.mjs` 注释："兄弟倒序压栈后取正序"），
所以同一份 `.gil` 在**插件预览**里看起来会是 pages 盖住按钮 —— 这不是 bug。
若真编辑器里看着也是反的，加 `--order=spec` 重跑即可（一行开关）。

## 九、踩到的坑（都付了代价，写下来防复发）

1. **几何层级深一层**（第四节）：`pairOf(状态包装,502)` 拿到的是整个几何容器，`setPair` 把它写没了。
   症状：记录"状态=0"、几何槽 327B→84B、`recordsOf` 认出的记录数**从 63 掉到 45**（拉伸类全丢）。
2. **`stateBlocks()` 漏判全零几何**：它要求尺寸对里有 2 个浮点，`(0,0)` 是空消息。
   ⇒ 整屏拉伸容器被读成"状态=0"。断言必须按**结构**找，不能按"有值"找。
3. **`slot (2,15)` 没有 `#503` details**：类型名/实例名直接在 `#505/#12/#501`。
   而 `(64,84)`/`(73,96)` 有 `#503` details。写工具时这两个访问器必须分开，否则改名报"找不到槽"。
4. **写纯 id 列表后必须 `sub = null`**：`encodeMsg()` 对 `wt2` 只有"字段号==503 且 payload 是纯 id 列表"
   才走 payload，否则**优先走 `sub`**。`/#9/#501` 不是 503 ⇒ 只改 payload 不改 sub 会被静默忽略。
5. **图片供体自带一条父指针** `#504=1073741888`：不覆盖就会在别人家记录里当孤儿；克隆后断言
   "记录里的 ID 引用只能是【自己】或【新父】"，多余就是悬挂引用。
6. **转换器写死找名为 `root` 的控件**（murdoku 的命名），本工程根叫 `app.root`
   ⇒ 原版 `gil_to_save.mjs` 生成出来的存档**控件树是空的**（`tree` 只有画布，outBytes 5KB）。
   修法：把转换器**复制到工作区**（repo 只读）加 `--root-name=`，见 `tools/gil_to_save_ws.mjs` 头部。
7. `gil_slots.mjs` 有个小 bug（把状态块对象当数组传给 summarize）已就地修掉。

## 六、GUID 撞号（2026-10-21 真机导入实测 + 历史资料）

### 现象
第一版 `473-教程UI系统骨架-v1.gil` 导入真机后，编辑器弹「试玩校验失败 → 界面控件设置错误 →

### 排查（结论：我们的文件内部是干净的）
`tools/gil_dupid.mjs` 按 `回执-GUID根因-v259` 的判据扫描（一条控件的 GUID 在 .gil 里存多处：
`/#501` 顶层、`/#502/#11/#501` info 包装、`/#505/…#503/#504/#4` 槽内回指）：

```
★ 被 ≥2 条记录认领的 id：0 个
全部记录都恰好 1 个 recordId + ≥1 个 infoGuid ✓
```

⇒ 不是"克隆只改顶层 #501"那类内部重复（v259 的真因），而是 **v257b 那类"我的文件和目标工程撞号"**：
1073742041 是我们的 `btn.close`，而目标工程里编辑器自己已经有一个控件占着这个号（报错文案里的"开关控件"）。

### 修法（照 v257b 的做法：新增控件搬到高号段）
`build_gil.mjs` 的 id 分配从 `maxId + 1` 改成 **固定高号段**：

```js
const ID_BASE = Number(argOf('base') || 1073743800);   // 新增控件一律从这里起
```

- 历史对照：v257b 当年也是把新控件从 1073742786… 搬到 **1073743794+** 才通过；
- 新档 `474-教程UI系统骨架-v2.gil`：新 id **1073743800…1073743838**，与基线（1073742016–2039）
  和目标工程已用号段都拉开；
- 自查：`gil_dupid` 0 重复 · `roundtrip` 逐字节一致 · `gil_geom_diff 473 474` ⇒ **逐条同构，只差 id 值**。

### 以后再遇到"GUID 重复"
1. 先跑 `node tools/gil_dupid.mjs <档>` 判断是**内部重复**（≥2 条记录认领同一 id）还是外部撞号（0 重复）；
