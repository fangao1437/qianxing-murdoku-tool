# 家具美术制作流程（完整版）

> 这份文档是"美术侧从原作参考做到真机显示"的**全流程**，按实际跑通的顺序写；
> 每一步都标注 **输入 → 输出 → 校验**，并附上我们踩过的坑（§7）。

---

## 0 流程总览

```
① 参考与量测        原作图标 → 长边占格 / 主色 / 部件几何
② 部件与层表        每件 9~12 层（手搭）或 N 层（模板，层数不限）
③ 规格数据          家具模板层规格 JSON（本仓库 specs/）
④ 存档写入          模板 pair（源+母本）+ content（两份）+ 图片层；things 引用控件
⑤ 运行时约定        face → 地毯 → 家具 → 覆盖层；缩放/跨格/切关
⑥ 离线预览与校验    check-spec / slice-layout / render-preview / test
⑦ 真机验收          日志两类行 + 视觉层级 + 切关清理
```

---

## 1 参考与量测

**输入**：原作画面/图标（只在美术侧本地使用，**不入库**）。
**输出**：每件家具的：
1. **长边占格**（实测，决定模板画布与运行时尺寸）：

| 家具 | 长边（格） | 依据 |
|---|---|---|
| 椅子 | 0.836 | 原作图标内容框 / 格子像素 |
| 桌子（方/长） | 0.836（两格长桌长边 = 2×0.836） | 同上 |
| 书架 | 0.821 | 同上 |
| 植物 | 0.760 | 同上 |
| 雕像 | 0.912 | 同上 |

2. **主色**（用取色器量：桌面 `#AD9C67`、桌沿 `#8C7F52`、椅子奶白 `#FEF7E4` + 棕金 `#D9C08A`、
   植物叶 `#79CFA1` + 盆 `#FCA161`、石材 `#C9C9D2`、地毯外框/内面/内线 `#B89A62 / #DCC684 / #C9B072`）；
3. **部件几何**（从参考里量比例：如桌子=桌面 81% 高 + 黑分隔线 + 深色桌沿 + 两条腿）。

> 参考图只用于量测；仓库里只保存 **id / 颜色 / 尺寸 / 几何**。

## 2 部件与层表

两条路线，**同一条"层表"数据模型**：

| 路线 | 层数上限 | 适用 |
|---|---|---|
| **手搭层**（旧） | ≤12（格子模板的 obj…obj12 层） | 桌子/书架/地毯这类"本来就能用少量层表达"的 |
| **模板层**（当前） | **不限**（一个模板引用控件只占 1 层） | 椅子/植物/雕像/地毯这类"想多细就多细"的 |

层表每行 = 一条图元：
`{ imageId（100001/100002/107102/106056）, color(0xAARRGGBB), w, h, dx, dy_down }`
（单位：模板 content 画布像素；基准 1 格 = 108px；`dy_down` 向下为正）

**约束（工具会校验）**：
- 只用官方**基础形状**素材（矩形/椭圆/圆角板/柔光圆）；
- **全部轴对齐**（不依赖旋转）——早期旋转细椭圆在真机发毛；
- 层序从下到上（`order` 从 1 连续）；
- 尺寸 ≤240px、>0；颜色格式 `0xAARRGGBB`。

示例（8 个模板的完整层表）：`specs/furniture_templates.json`。

## 3 规格数据（本仓库这一步）

```bash
# 从主项目的手写层表（lua/furn_art.lua）生成规格
node art/tools/gen-layers.mjs --furn-art=<主项目>/lua/furn_art.lua --out=out/furniture_templates.json --check
```
- `--check` 会把生成结果和 `specs/furniture_templates.json` 逐层比对（容差 0.011px）；
- 地毯（rug）在 `lua/furn_art.lua` 里是**程序化**的（3 层矩形按包围盒切片），本工具把它固化成
  一个模板层表（108 / 82.1 / 64.8 三层居中）；
- 输出就是交给 `.gil` 写入的**唯一数据源**。

## 4 存档写入（`.gil` 工具链负责，本仓库只给数据）

### 4.1 模板 pair（源 + 母本）
每个模板 = **两条记录**：
- **源**：无父、组件 `[1,2,4]`，`#502[4]/#14` → 母本；
- **母本**：父 = 模板容器（`1073741844`），组件 `[1,2,3]`，`#502[3]/#13` → 源；
- 模板**根**尺寸按编辑器习惯（家具类 150×150）；
- **两份 content**（源一份、母本一份），画布 = 1 格基准：`108×108`；长桌 `216×108` / `108×216`；
- content 的**子列表** = N 个图片控件（`imageId`、`imageColor`、`sizeDelta`、`anchoredPosition` 照规格）。

### 4.2 `things` 容器 + 引用控件
- `root/things`（隐藏容器）下放 **每个模板 1 个模板引用控件**（66/89 槽），
  **引用值 = 模板的【源】GUID**（不是母本！）；
- 脚本运行时读 `things` 子控件的 `referencedPrefabIndex` 建映射，**不依赖硬编码 GUID**。

### 4.3 记录预算（官方《编辑项范围限制》）
| 项 | 上限 |
|---|---|
| 单个界面控件组内界面控件 | **1000**（控件组画布 = `root` 树） |
| 自定义控件模板数量 | **2000**（按模板个数，不按模板内层数） |
| 单次玩家屏幕内可显示控件 | **10000**（运行时实例 + 模板展开都算） |

> 模板内的层不占"控件组 1000"；但**每层在 `.gil` 里是 1 条记录 ×2（源/母本两份）**，
> 写入工具要按文件体积/导入时间自行评估。

## 5 运行时约定（脚本侧已实现，供核对）

```
格子 cell.r.c（cell 模板实例）
 └─ content
      ├─ face          ← 每格实例化 `cell.face` 模板，命名 face，Sibling 0（地板）
      ├─ furni.<cell>|<kind>  ← 家具模板实例：地毯 Sibling 1、其它家具 Sibling 2
      └─ hint / wall.* / door.* / note / portrait / x   ← 静态覆盖层（在家具之上）
```

- **face**：`cell.face` 源 GUID = 1073747145（母本 = 旧 face#1073741882）；
  脚本给每格 `content` 底部实例化，命名 `face`，于是原有的"房间染色/头像/可见性"写入自动换绑；
- **家具**：`furn_level` 属性到达 → 读 `things` 映射 → 每件 `InstantiateClientUIControl(模板源, 格子 content)`
  → 尺寸 = 跨格×格子、位置 = 整件中心相对锚点格中心 → `SetSiblingIndex`（地毯 1、其它 2）；
- **缩放**：模板层按 108 基准写死，实例内层按 `f = 格子宽 / 108` 缩放（5×5 是 1:1，6×6 ≈0.83）；
- **切关**：销毁上一关实例、清缓存；属性先到/后到都能收敛（补造机制）。

## 6 离线预览与校验

```bash
node art/tools/check-spec.mjs              # 规格自检
node art/tools/slice-layout.mjs --layout=art/examples/level-demo.json
node art/tools/render-preview.mjs --layout=... --spec=... --out=out/art-preview.svg
node art/test/run.mjs --furn-art=<主项目>/lua/furn_art.lua
```

`render-preview` 复刻游戏内棋盘几何（1600×900；棋盘框 584×584 @(608,138)、边框 12px、格间距 4px），
把**规格层表**按"锚点格 + 跨格 + 偏移"摆出来 → 得到与真机一致的观感基准（SVG，零依赖）。

**验收看什么**：
1. 每件家具的形体/比例/配色与原作参考是否接近；
2. 跨格件（长桌/地毯）是否**整件连续**、没有在格子缝里断开；
3. 层级：家具不盖头像/墙/门/笔记；
4. 地毯边框只在整块外侧（不是每个格子一圈）。

## 7 真机验收 & 已知硬坑

### 7.1 真机日志（两类行）
```
[murdoku] 面层：cell=1.1 实例化 face（prefab=1073747145，尺寸=108px）
[murdoku] 家具模板：cell=1.2 ← furn.table.h2（prefab=1073747138，父控件=content）
```
- 两行都有但画面空 ⇒ 查实例的 `parent/visible/GetChildren` 与 `content` 子控件顺序、以及各"只藏不显"通道；
- 一行都没有 ⇒ 查属性投递/`things` 读取。

### 7.2 坑（都是实测踩出来的）
1. **编辑器"打开→保存"会删掉纯手写的模板记录**：实测 678 条 → 491 条，被删的 205 条正是手写模板/content/层。
   ⇒ 模板必须"编辑器里建过"，手写内容是否被保留要用副本验证；**别拿"手写模板"当最终交付**。
2. **引用值指向模板【源】GUID**（不是母本）。
3. **模板根 150×150、content 画布 108×108**：108 是 content 画布，不是模板根；写错会导致"预览有、试玩没有"。
4. **不要用旋转细图元**：真机上 1~2px 的旋转椭圆会抖/发毛。
5. **透明背景**：若用外部"图片→图元"压缩管线，输入只吃 RGB（透明会变黑）⇒ 裁 bbox + 按 alpha 掩码过滤块。
6. **控件组上限 1000**（画布内）、模板 ≤2000、屏上 ≤10000：静态塞图元会撞，运行时实例化/模板展开要算预算。
7. **合规**：仓库只存 id/颜色/尺寸/几何；官方贴图、`.gil`/`.gia`、截图一律不入库。
