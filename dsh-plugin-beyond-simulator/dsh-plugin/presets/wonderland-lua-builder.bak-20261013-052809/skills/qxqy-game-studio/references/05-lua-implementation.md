# 5 Lua 实现

**什么时候是这一步**：要开始搭、写或修游戏。

**做完的标志**：可加载的 Lua + 完整存档 + 挂载/架构说明；目标用例走过有效的 Red→Green→Regress。

**从本步骤开始操作模拟器。**

---

## 怎么想

### 先建能加载的最小骨架，再谈 Red

坏 JSON、路径错误、挂载错、事件到不了控件、模拟器没启动、工具故障——**这些都不算 Red**。先把它们排除掉，剩下的失败才是"目标行为确实还没实现"。

新游戏的 `first-success`、`first-fail`、`restart` 至少各要有一次**有效 Red**。保留 `failedAt`、帧号与现场快照。

已有完整行为的工程**不要为了制造 Red 去删生产代码**。

### 一次实现一条规则（P10）

同时改多处，失败后无法归因。窄改动按风险检查即可，不要人为制造失败。

### 用查询代替假设（P11）

写依赖编辑器 API 的 Lua 之前，**回头核对官方 2D/Lua 文档**（路线见 [workflow.md 知识库核验](workflow.md#知识库核验)）。

- 不要从普通 Lua/UI 框架或 3D 节点图经验**猜**接口。
- 语义不明时：查文档，或做一个**单问题探针**。探针不进生产路径。
- 新增 API 资料缺失时，先查已配置来源，只请用户补**仍然缺的**那一份。

### 静默失败要出声（P11）

模拟器有几条**不报错但不生效**的路径。写代码时对每个降级/跳过/提前返回都打一条日志说明条件；否则整个子系统被跳过而毫无症状。

## 工具接入

用**当前宿主实际提供的**工具说明与 schema。

- 有 `qxqy-simulator` 操作技能时按需加载（MCP 不会自动附带该技能）。
- MCP 宿主还需要 `handle`：先 `qxqy_project_open`，之后每个工程操作都带该句柄。**不要照搬 Harness 示例而漏参数**；Harness 没有 `qxqy_project_open`。

### 工程与存档纪律

- **三类资产**：服务端 UI 容器、客户端 UI 模板、Lua 脚本。脚本只挂客户端控件/模板；服务端的"客户端控件容器"不能挂脚本。
- **数据写操作尽量带最新 `expectedRevision`**（省略时按内存当前状态直接生效，可能覆盖别人的改动）；成功后 revision +1；冲突时重新 `get` 再算，不要盲目重试。
- 内存修改与试玩**不会自动落盘**，而 Harness 工具集里**没有保存操作**：落盘要请用户在"模拟器"标签点【保存存档】。
- 目标路径 `workspace/<slug>/<slug>.save.json`（文件头附近含 `"format": "qxqy-simulator-save"`）。
- 需要真机脚本复制时，**必须先让用户保存，且保存后不再改动存档**，否则复制会被拒。

## 实现规则

| 主题 | 规则 |
|---|---|
| 时间 | 计时显式消费 `dt`；随机玩法用可注入 seed/序列；规则与 UI 副作用分离 |
| 调用约定 | `game` 是全局表：用点号 `game.X(...)`，注意参数个数。误用冒号**在模拟器可能静默通过、真机报错** |
| 图片 | `SetImage(imageSource, imageId)`；`imageId` 只读；两者成对匹配 |
| 文本 | 属性写不进去时（`.text` 可能为 nil）退回 `SetText`；保留必要 `pcall` 层级，不要为"统一写法"删掉容错层 |
| 输入 | **没有长按事件**：用 CursorDown/CursorUp + 显式 `dt` 累计实现，并定义阈值与取消条件。容器 `showCursor` 必须为真，光标事件才有效 |
| 事件 | 按键回调返回 boolean 表示"已处理"，否则同容器其它控件会重复响应；按键按渲染顺序派发 |
| 服务端 | Lua 只读变量 + `SendSignal()`；**不能写自定义变量**；变量变更回调不给值，需自行 Get；联机信号最低 100ms |
| 控件创建 | 优先"少量基础模板 + Lua 实例化/改属性"。官方限制：**只有存为模板的客户端控件的父节点能被动态创建** |
| require | 用导入根前缀：`workspace/<slug>/draws.lua` → `pcall(require, "default_import_file/workspace/<slug>/draws")` |
| 规模 | 注意逐帧工作与控件数量。循环内高频调用会导致进关卡死**且日志不报错** |
| GIA | 目前认识不完整：在 UI 侧直接定义复杂控件树或属性，导出或真机导入可能不兼容。按需导出；**GIA 不保存脚本挂载关系**，挂载点要单独记录 |

### 布局

- **原点左下、锚点相对父矩形 0–1**。注意官方 `GetAnchoredPosition` 在**有父级**时是相对父层级**中心**的偏移——两套基准不要混用。
- 以 `mobile-16-9`（1280×720）**整屏完整可见**为基准；PC 用固定设计板 `min(canvas/design)` 等比放大、不足留边。
- **缩放容器上不要再加全屏不透明的兄弟节点**（同级先出现的子节点会盖住舞台）。
- 接入步骤 4 的素材；缺失框记录真实 `targetId`。
- 文本框建议开 `adaptiveFontSize = true` 并设最小字号；`fontSize`/`minimumFontSize` **必须是整数**。自适应字号与换行在模拟器上不完整，真机确认文字是否完整可读。
- **旋转会进入运行时，但点击命中按旋转前的轴对齐矩形算**。需要"看得见也点得到"时，别用旋转做命中区域。

### 脚本源码的双份真相

`scripts[].source` **非空时**试玩运行的是内联源码。**只改外部 `.lua` 而不同步内联源码 = 仍然跑旧代码。**

每次改脚本后**两处一起同步**，并**两处都读回确认**（P5）。

## Red → Green → Regress

1. **建可加载的最小骨架**，排除环境故障。
2. **跑步骤 2 的用例**，确认目标行为缺失导致**有效 Red**。保留 `failedAt`、帧号与现场快照。
3. **一次实现一条规则**，跑目标 Green 与相关 Regress。已有规则缺陷先补最小失败用例。
4. **断言双向**（P3）：改了什么，就同时断言"该变的变了""不该变的没变"。
5. **确认测试真的跑到了新代码**（P7）：有打包/拷贝环节时先重新打包，否则绿灯没有意义。
6. **写入生效检查**（P5）：请用户保存落盘后，从磁盘重新读取并做**字段 diff**。往返字节相等不能证明生效；"工具返回成功"也不是证据。
7. **按名字回归，不按数量回归**（P9）。

记录格式（够用即可，不必逐项凑）：

```text
case / red reason / failedAt / frame
minimal change / target result / full regression
screenshot or snapshot / remaining risk
```

**只按策划契约实现玩法，不逐行翻译 HTML DOM/CSS/JavaScript。**

## 性能与度量

先测量再优化。**测量的树必须与真实结构一致**——用与真实结构不符的替代树做探针，会把开销记到错误的版本上（见 [P2](reasoning-patterns.md#p2--度量先验真) 里那次被推翻的 972→132）。

汇报性能时写明**工具、粒度与样本**。**没有真机数据就不要给毫秒结论。**

## 上下文与产物

- **每轮至多一次昂贵快照调用**（`get`/`load`/大 `patch`），让那一次同时回答多个问题；其余用便宜探针。

- 维护 `docs/tech-architecture.md`：Lua 文件、控件/容器、服务端变量/信号的职责，关键数据流与脚本挂载点。**结构变化才更新**——交付后它是运维手册，过期条目比没有更糟。
