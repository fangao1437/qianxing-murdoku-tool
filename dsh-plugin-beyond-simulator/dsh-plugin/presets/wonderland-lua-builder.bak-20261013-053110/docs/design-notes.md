# 设计说明：两个预设为什么要这样改

本文件记录 2026-10-13 第二轮改版的判断依据、取舍与代价。它不是使用说明（那是 `README.md`），也不是变更清单（那是 `CHANGELOG.md`），而是**决策的理由**——目的是让后来改这个预设的人知道哪些约束是有意的、哪些是可以推翻的。

---

## 0. 一句话结论

上一轮改版把「精准」实现成了**更多的规则**；这一轮要把它实现成**更少的猜测**。

- 把「事实的精准」推到按需查阅的位置（它消除猜测，因此释放思考）
- 把「流程的精准」大幅削减（它消耗注意力，却买不到判断力）
- 用几个**能自我证伪的推理姿态**替换几十条只在已知情形下成立的禁令

---

## 1. 为什么「更多规则」买不到严谨

### 1.1 外部证据

Eliav 2026（[arXiv 2607.19257](https://ar5iv.labs.arxiv.org/html/2607.19257)，5 个模型 × 4 种格式 × 2 种放置位置，960 次调用/模型）测的是**可程序化验证的规则条数**与遵守率的关系：

| N（同时生效的规则数） | 10 | 20 | 40 | 80 | 120 | 160 |
|---|---|---|---|---|---|---|
| Sonnet 5 全对率 | 0.938 | 0.750 | 0.238 | **0.000** | 0.000 | 0.000 |
| Claude Haiku 全对率 | 0.850 | 0.594 | 0.119 | **0.000** | 0.000 | 0.000 |
| Gemini Flash 全对率 | 0.919 | 0.825 | 0.312 | 0.019 | 0.000 | 0.000 |

要点：
1. **N=80 是硬地板**，5 个模型、4 种格式、两种放置位置全部归零。不是渐进下降，是断崖。
2. **markdown 没有可靠优势**；Qwen 35B 反而稳定偏好纯文本（N=160 时差 4.8pp）。
3. 格式的 token 开销：markdown ×1.258、prose ×1.221、table ×1.367（相对纯文本）。

### 1.2 本预设的实际条数

`platform-facts.md` 30KB，`SKILL.md` 的「全局硬规则」9 条，加上 7 份步骤文档里的清单与表格，以及两版 persona 各约 6300 字符。按 N=80 的地板算，**这个预设远超任何模型能同时遵守的规则预算**。也就是说：规则越多，实际生效的越少，而**哪几条生效是不可控的**。

这解释了一个真实症状：同一个预设，有时严守某条红线，有时无视另一条，且复现不出来。

### 1.3 内部证据：验证器把「填模板」变成了目标

`tools/verify.mjs` 检查的是**符号是否在场**：

```js
for (const token of ['文本框','文本视窗','预设按钮','光标检测区域','网格视窗',
                     '模板引用控件','界面动效','全屏动效','预览限制']) {
  if (!facts.includes(token)) bad(`platform-facts.md is missing required fact/token: ${token}`);
}
```

这类检查**只能**奖励「把词写进去」。它不能奖励「这条规则让某个人少犯了一个错」。上一轮为了通过自检而不断补规则，是**结构性**的，不是某个人偷懒。

> 结论：验证器必须换成检查**判断力**（有没有说清什么会推翻自己、有没有给出可执行的探针），而不是检查**词汇量**。

## 2. 真正制造「模板化」的六种机制

按上一轮语料逐条对照后，公式感的来源不是文风，是下面六件事：

**M1 · 强制清单。** 「分析完整性清单（逐项给结论，不适用就写"不适用"）」——即使"首 30 秒"对当前项目无意义，也必须写"不适用"。**填格子取代了判断**：产出变多，思考变少。

**M2 · 流程门绑定了认知门。** 「步骤 1–4 不打开模拟器」被写死。但一个 30 秒的探针可能正是设计所依赖的事实；禁令迫使代理**猜**而不是**查**——恰好与"降低猜测"相反。

**M3 · 模板先行。** `01-game-design.md` 内嵌一份 ~70 行的 GDD 模板。代理的注意力从"这个玩法成不成立"转向"把表填齐"。

**M4 · 先验结论。** 「核心循环必须能写成一句：`目标 → 操作 → 即时反馈 → …`」。有些成熟的玩法（涌现式、沙盒式、节奏式）不适合这个句式；强制它会**剪掉**本可以成立的方案。

**M5 · 仪式化标签。** 「证据登记表」要求每条结论填 标签/来源/复核方式/有效期 五列。"不适用就写不适用"式的元数据，在无证据可记时也照填。

**M6 · 注意力稀释。** 关键红线（存档权威结构、内联 source 优先、只有模板父节点可实例化）与礼貌性建议（"不需要报告全部配置清单"）处在同一个列表层级、同一种语气里。**读者无法分辨哪条会毁掉项目。**

## 3. 要引入的六个「推理姿态」

用**能自我证伪的姿态**替换只在已知情形下成立的禁令。姿态的特征是：它不告诉你结论，它告诉你什么样的结论还不配被相信。

| 姿态 | 一句话 | 它替换掉的东西 | 它防止的错误 |
|---|---|---|---|
| **P1 预写推翻条件** | 下结论前先写"什么观察会让我改判"，再去找那个观察 | 一次性断言 + 事后补来源 | 结论固化；测量保真事故 |
| **P2 度量先验真** | 任何计数/性能/结构结论，先证明测量工具遍历的对象和真实对象是同一个 | 「探针给数→写进报告」 | 972→132 那类被推翻的结论 |
| **P3 两向断言** | 每个状态变化同时断言"该发生的发生了"和"不该发生的没发生" | 单向"绿灯"断言 | 假绿；删掉代码后测试依然通过 |
| **P4 先分叉再收敛** | 设计阶段先给出 2–3 个**机制不同**的方案与各自代价，再选 | 直接填空进模板 | 第一个想到的方案即唯一方案 |
| **P5 读回才算写入** | 落盘后从磁盘回读并做字段 diff；成功返回不算生效 | 信任工具返回值 | 内联 source 未同步、静默 no-op |
| **P6 结论即假设** | 注释、旧文档、上一轮交接、**包括本预设自己**都是待复核的假设 | 引用文档即定论 | 过期文档被当权威 |

关键差别：这六条**不依赖具体平台**，因此在没被枚举到的新情形下依然可用。而"点击前必须传 canvasId"只在那个工具的那个版本成立。

## 4. 信息分层：什么必须常驻，什么按需查

判断标准只有一条：**错过了它，会不会写出一份必须推倒重来的东西？**

### 常驻（错了就白干）
- 交付物是「模拟器/真机能跑的 Lua + 完整存档」，不是网页
- 坐标系：千星原点左下，HTML 原点左上，禁止抄像素
- 客户端 Lua **不能写**自定义变量（读变量、发信号）
- 只有**存为模板控件的父节点**能被 `InstantiateClientUIControl` 创建
- 树权威结构是 `root.children`（`tree[].parentId` 无效）；非空内联 `scripts[].source` 优先于路径文件
- **没有保存工具**：落盘要请用户点【保存存档】
- 模拟器通过 ≠ 真机通过；两侧都缺才是真缺陷
- 2D 语料路线：`miliastra-knowledge-lua` + `list_client_documents` / `get_client_document`；`rag_search` 只覆盖 3D 服务端

### 按需查阅（改成"用到再取"）
用例 schema 的每个断言字段、patch op 子集、`require` 前缀、字号与单位规则、GIA 往返细节、每个工具动作的超时、Windows 引号与编码陷阱、11 类控件全表、素材预览版本差异。

### 直接删除
- 把 GDD 模板从步骤文档移到产物本身（写一次，不是读一次）
- "分析完整性清单"由强制清单改为**按需提问**
- 重复陈述；与判断无关的排比句

## 5. 两个预设的分工

两个预设共享同一套 skills 语料（同一份事实、同一套姿态），差异只在 persona 与放行范围：

| | `wonderland-lua-builder`（基础版） | `wonderland-lua-precise`（精准版） |
|---|---|---|
| 定位 | 日常开发、窄修复 | 交付、真机同步、性能与结构结论 |
| 姿态 | P4 分叉 + P5 读回 + P6 假设 | 全部六条，且 P1/P2 强制 |
| 手段 | 少了 P1/P2 的强制形式 | 增加「预写推翻条件」与「度量先验真」的**具体触发条件** |

**精准版不靠"多写规则"变精准，靠"多要求一次自我证伪"变精准。** 这是本轮最关键的设计决定：精准版的增量应当是**质**的（多一轮反证），不是**量**的（多十条禁令）。

## 6. 自检要跟着改

`verify.mjs` 从"检查关键词在场"改成检查判断力：

1. **规则预算**：统计 persona 与语料中的祈使句条数，超出预算即失败（预算值见下）。
2. **姿态在场**：六个姿态各自至少出现一次，且**带触发条件**（不是口号）。
3. **事实仍准**：保留关键平台事实的在场检查（这一半是好的），但只保留"错了要推倒重来"的那批。
4. **不重复**：同一事实在两个文件里出现即告警（消除 M6）。
5. **无强制清单**：出现"逐项给结论""必须写成一句""不适用就写不适用"这类措辞即失败。

> 代价：自检变弱的地方是「无法再保证某个具体事实一定被读到」。这个代价是**有意接受**的——因为原来那个保证是假的（N=80 地板）。

---

## 7. 已知取舍与风险

1. **删减可能删掉有用的东西。** 缓解：被删内容进按需附录，不直接消失；本文件记录每一处删除的理由。
2. **语料变短后，行为可能不如旧版"看起来勤快"。** 这是设计目标，不是回归。判断标准应是「返工次数、被推翻的结论数」，而不是「产出文档的页数」。
3. **两个预设仍共享 skills 语料。** 若将来必须让精准版带不同事实，需要在 build 流程里按变体分发 skills 目录；本轮不做。
4. **`verify.mjs` 变弱后，需要人复核语料质量。** 因此本轮把评测（`evals/agent-behavior.md`）从"检查是否提到某概念"改成"给定场景，代理是否做出可证伪的判断"。

---

## 8. 判断这轮改版是否成功的标准

不看文档长度，看这五个可观察量：

1. 同一事实在语料中只剩下**一个**权威位置。
2. 关键红线**没有被埋在**长列表里（能一眼找到）。
3. 代理面对**语料未枚举**的新情形时，仍会去查证而不是猜（这是姿态是否生效的直接检验）。
4. 出现"我原以为 X，测出来是 Y"的记录——说明 P1/P2 在起作用。
5. 用户不再需要反复提醒同一条规则。
