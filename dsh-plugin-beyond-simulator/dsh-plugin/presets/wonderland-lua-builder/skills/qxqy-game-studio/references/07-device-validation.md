# 7. 真机试玩验证与 bug 修复

## 输入与适用时机

读模拟器候选、测试记录、资产清单、导出警告与已有真机回传；回读 [平台事实 §5 模拟器 vs 真机差异](platform-facts.md#5-模拟器-vs-真机差异实测换版本要复核)。直接复用用户已提供的索引、画面与日志，只询问缺项。

## 准备交付说明

在 `docs/device-handoff.md`（或项目已有交付说明）写清本项目实际需要的操作：交付文件与版本、资产导入顺序、入口脚本与挂载对象、需要核对的控件/模板、脚本路径、试玩步骤与预期、已知限制与未验证项。只列本项目真正需要的项；**导出文件路径不等于真机已导入**。

- GIA 不保存脚本挂载关系，也不保存脚本同步配置：脚本映射与挂载必须单列。
- 交付清单写成**可逐条执行的步骤**，每条带"预期结果 + 回传格式"；不要把脚本头部注释里的功能直接抄成"已实现"——先确认该功能真的存在，未做的明确标"未构建"。
- 已有的正确映射与挂载直接复用，只说明本轮新增或变化项。

## 用户导入时需要完成什么

| 环节 | 用户操作 / 回传 | AI 配合 |
|---|---|---|
| 导入与挂载 | 导入本轮所需资产，核对脚本映射路径，把入口脚本挂到指定客户端控件/容器节点或模板 | 给"哪个文件 → 哪个资产/挂载对象"的对应关系与本轮变化项 |
| 核对真实索引 | 检查导入后目标控件/模板的实际索引；有变化时给资产/控件名、原值（若已知）、新值 | 按控件身份校准工程与脚本；复用已有回传，不重复索取 |
| 绑定后续更新位置 | 若要用本机脚本同步，确认账号、关卡与导入脚本目录 | 准备路径对应关系、保存配置、预览差异 |
| 更新脚本 | 在"Lua 脚本 → 实机脚本同步"检查源文件、目标路径与差异，选择文件并确认复制 | 完成源码与索引修复、保存工程，指出新增脚本仍需建立的映射/挂载 |
| 保存与试玩 | 在千星沙箱保存并重新试玩，按清单走开局、成功/失败、重开及本轮变更，回传异常步骤与画面/日志 | 对照预期定位问题、修复并给下一轮更新与回归步骤 |

绑定同步目录只是便于后续更新的可选项；没有本机目录访问能力时仍可交付 Lua 与明确的手动更新路径，不以绑定目录作为真机验证前提。

## 导入后的索引校准

以**真实编辑器的索引为准**。按当前模拟器接口的 `setControlGuid` / `controlGuidChanges` 流程处理；用户手工改过、没有生成记录时，仍要按控件身份核对，不能只看记录是否为空：

1. 按资产与控件身份读变更记录，把连续 A→B→C 解析为**最终**索引；同一 `batchId` 是一批同时映射，不能逐条替换数字；不能把模板索引和运行时控件 `Id` 混用。
2. 检查存档 `scripts[].source`、路径源码、常量、配置表、别名与身份校验，按语义同步到最终索引。**非空内联源码优先执行，不能只改外部 `.lua`。**
3. 复核旧值残留，保留同值但无关的图片 ID、脚本映射 ID 等数值。无法读取或无法判定的引用保留待处理。
4. 仅当相关引用全部同步、或确认无引用后，用最新 revision 调 `acknowledgeControlGuidChanges{changeIds}`；不清空未处理项。
5. 请用户保存完整存档，重启试玩并回归创建、身份检查与受影响流程，再做真机验证。

2.0.8 没有控件索引的批量同步/自动替换工具：这条必须**按语义手工做**，不要承诺"一键全量替换"，也不要用全局数字替换。三方核对（索引记录 / 存档源码 / 工作区 `.lua`）缺一不可。`qxqy-simulator` 操作说明提供完整校准流程；MCP 另需 `handle`，以当前 schema 为准。

## 绑定导入后的脚本存储位置

先读存档已有同步配置；缺少时由 AI 发现候选并请用户确认目标账号/关卡，或使用用户已明确提供的路径。多个候选不能只按最近修改时间猜选。

| 配置项 | 含义 |
|---|---|
| 项目脚本文件夹 `workspaceDir` | 本项目在工作区内的相对目录，例如 `workspace/my-game` |
| 千星沙箱脚本文件夹 `clientImportRoot` | 当前账号/关卡实际的 `external_lua_file/default_import_file` **绝对**路径 |
| 游戏里的项目子文件夹 `clientSubdir` | 保留导入后脚本映射的相对路径，通常与工作区项目目录同值 |

目标文件 = `<clientImportRoot>/<clientSubdir>/<脚本相对路径>`；保留目录层级，不按文件名平铺。改动路径后核对真实编辑器的映射是否仍指向它。

这些路径属于**运行模拟器服务的机器**：远程 Web/MCP 不能把浏览器所在电脑的路径当作服务端可访问路径。目录绑定随完整存档保存，不写入 GIA，**不会建立实时或双向同步**。

## 后续让 AI 配合更新脚本

AI 可调用 `qxqy_script_sync` 的 `discover/status/configure/preview`：发现目录、读写配置、预览差异；**没有 apply**，复制只能由用户在编辑器确认。调用前以当前工具 schema 为准。MCP 宿主才需要 `handle`（本 Harness 环境没有安装 MCP 工具体，`qxqy_project_*` 之类不可用）；`discover` 会扫描本机 `BeyondLocal\<uid>\Beyond_Local_Save_Level\<editorId>\external_lua_file\default_import_file` 下的候选目录。

1. **对齐当前版本。** 先核对索引变更、工作区源码、存档内联源码与已知的实机手改。非空白内联 `source` 优先，否则读 `path`；不能只改磁盘文件就默认同步的是新内容。发现实机独有修改先比较并合并回项目，有真实冲突再请用户判断。
2. **保存并预览差异。** 先完成引用修复与已核验变更的确认，**请用户在"模拟器"标签点【保存存档】**（Harness 没有 AI 侧保存工具；复制要求存档已保存且之后未再改动），再预览每个脚本的来源、目标与新增/覆盖内容。AI 只能说"已准备更新"，**复制前不能说"已同步到真机"**。
3. **用户确认复制。** 请用户在 Web/DSH 编辑器「Lua 脚本 → 实机脚本同步」执行"保存存档并查看更新"，选择文件并确认复制。存在**未确认的 `controlGuidChanges` 时复制会被直接拒绝**，先处理完再预览。MCP 与 Web 各有会话：先在 Web `/editor` 加载 AI 保存的同一存档，再重新预览；只读预览页不能执行复制，MCP 的预览计划也不能跨进程使用。AI 不调用人工复制端点，不用 shell 或目录联接绕过本次确认。
4. **核对结果再试玩。** 记录复制回执中的成功/失败与备份位置（备份在 `<workspace>/.qxqy-script-sync-backups/<planId>/`）。只同步存档登记的 Lua 脚本（含未挂载的 require 模块），不是整目录镜像；新增脚本仍须在真实编辑器建立映射和必要挂载；UI/模板结构变更另按实际情况重新交付资产。

已知会拒绝或失败的情形（先修掉再重试，不要反复重放）：计划过期（存档/源文件/目标已变 ⇒ 重新预览）；存在未确认的 `controlGuidChanges` ⇒ 拒绝复制；缺文件、目标重名、路径穿越、目标为符号链接 ⇒ 该行报错且不可选；源文件内容与预览不一致 ⇒ 会要求明确选择"用项目文件里的代码"；单个文件非原子，失败行单独报告。

用户选择手动更新时，给本次改动文件与准确目标路径，提醒保留实机已有修改；手改后把最终版本同步回项目，避免下一轮被旧存档覆盖。

### 同步是否真的生效

磁盘复制成功 ≠ 编辑器加载了新代码。用项目已有的导入/打包链路时，验证三件事：

1. **回执与校验和**：同步输出必须是成功结论（如 `done: synced N root(s).`），且每个目标的字节数/哈希与产物一致；出现大小或哈希不一致即失败。
2. **构建标记**：确认脚本内/日志里出现本轮的构建或版本标记行，证明编辑器读到的是本轮源码。
3. **每次测试前重做**：切换或新建关卡会产生新目录、可能仍指向旧脚本；不要依赖记下来的关卡 id，每轮试玩前重新同步。

记录"已复制到磁盘 / 编辑器已保存加载 / 真机已验证"三个不同状态，不承诺"绑定一次以后自动生效"。

## 缺陷修复与回归

请用户按交付清单实际试玩，记录真机环境、操作步骤、期望/实际、截图或日志与可复现性；证据标 `runtime=device` 并注明执行者与来源。

为每个真机缺陷建立最小复现，区分 Lua、素材、布局、模拟器差异与平台未知（用两侧判定规则）。先更新用例或明确人工检查，再修复，并重复模拟器与真机验证；保留修复前后证据。
用户手动改过的实机脚本，先核对并合并有效修改回工作区与存档源码，再进入下一轮。

## 产物与完成条件

产物为游戏资产、导入/挂载与实际索引记录、脚本路径与选定的更新方式、同步或手动更新结果、真机记录与修复记录。未完成的导入、挂载、引用修复、复制或真机检查分别列为待办。只有真机证据覆盖的目标行为可标通过；未回传或未覆盖的项目明确列出，交付状态保持**模拟器候选**。
