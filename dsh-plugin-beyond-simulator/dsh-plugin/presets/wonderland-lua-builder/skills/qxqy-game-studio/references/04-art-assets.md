# 4. 准备千星美术参考图和素材

## 输入与适用时机

读已确认的 HTML 效果、策划案中的美术意图与用户提供的参考。正式素材准备在 HTML 体验确认之后；本步骤不打开模拟器、不改存档。

## 执行动作

在 `docs/art-bible.md` 记录：体验形容词、主/辅/警示色、轮廓与层级规则、角色/道具识别特征、素材来源与用途、目标 `imageSource` + `imageId`/图元、模拟器占位方案、真机核验项。

有真正视觉分歧时，在**同一布局与同一玩法状态**下给少量可比较方向让用户选；没有分歧就直接采用推荐方向并说明理由。按工作区实际可用能力选用像素画、图元拟合、UI 制作或帧动画 Skill。

### 关键事实（决定方案怎么写）

- 官方原神/千星素材可以使用；`SetImage(imageSource, imageId)` 改图，`imageSource` 与 `imageId` **必须成对匹配**，不匹配同样显示缺失框。
- **模拟器预览范围随版本变化，先确认当前版本**：2.0.8 只把 `imageId` 100001–100006 画成基础图元代理（无素材下载链路）；2.1.x 起另支持固定白名单静态图片的按需下载与本地缓存，截图可用 `assetWarnings` 区分"下载失败"与"白名单外"。白名单外或加载失败仍显示缺失框——这是**预览限制，不是素材不可用**：照常选目标 ID，记录 `targetId`，真机核验"图对不对"；九宫格/动效与实际视觉同样留真机。
- 因此 P0 的**关键可读性不能只靠官方图片**：给每个关键元素配一个可在模拟器看清的替代（图元拟合、色块 + 文本、几何形状），把官方图片作为真机增强。
- 音频：Lua 有 `game.PlayAudio2D/StopAudio/IsAudioAlive`，但 2.0.8 模拟器不出声；音效不是可验证反馈通道，必须同时有视觉反馈。
- 区分**三层支持度**：能创建/保存 ≠ Lua 能读写 ≠ 试玩/真机真的生效。写方案时对每个视觉手段标明它属于哪一层，未验证的进真机清单。

### UI 还原规格

布局字段使用千星坐标约定：原点左下、锚点相对父矩形 0–1；**不写 DOM 选择器、CSS 类或 JS/Lua 函数名**。

| 字段 | 含义 |
|---|---|
| `id` / `kind` | 稳定控件名；`kind` 取官方 11 类之一：容器节点 / 文本框 / 文本视窗 / 图片 / 预设按钮 / 按键提示 / 光标检测区域 / 网格视窗 / 模板引用控件 / 界面动效 / 全屏动效 |
| `parent` / `anchor` / `offset` / `size` | 控件树与跨画布布局（PC 只做等比放大/留边） |
| `styleToken` / `assetId` | 色板、字号、间距与资产清单引用 |
| `visibleWhen` / `action` | 可见状态与抽象玩家动作 |
| `motionIntent` | 触发、时长、曲线与**可降级方式**（动效在模拟器是空操作，必须给出属性替代） |
| `fallback` | 模拟器看不清时的替代展示（图元/色块/文本） |
| `deviceCheck` | 需要在真机确认的项（真实图片、字号完整、动效） |

还原方式优先落到"少量基础模板 + Lua 实例化/改属性"；注意官方限制：**只有存为模板的客户端控件的父节点能被动态创建**，主屏控件与模板子节点都不行——这条会影响控件树设计，与本步骤的层级规划直接相关，方案里要写明哪一层是模板、哪一层是实例。

HTML（若存在）与 Lua 可以有不同适配层；稳定的状态、动作、控件与资产 id 必须可追踪。网页坐标不得进入 Lua。

### 成本控制

- 只做少量有差异的方向；高成本拼图或帧动画先准备**关键样本**，批量制作随步骤 5 的实现需要推进。
- 先定色板、字号、间距等 styleToken，再产出素材，避免返工。
- 每个目标 ID 记一行来源与用途，未知来源的标 `[推断]`。
