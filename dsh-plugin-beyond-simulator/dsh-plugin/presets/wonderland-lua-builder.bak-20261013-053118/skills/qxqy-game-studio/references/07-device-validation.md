# 7 真机验证

**什么时候是这一步**：准备交付，或处理真机回传。

**做完的标志**：目标行为有**真机证据**，或有一份写清"什么还没验"的清单。**未覆盖的项目明确列出，交付状态保持"模拟器候选"。**

---

## 怎么想

### 只有真机能证明真机（P14、P12）

模拟器绿只是**模拟器候选**。真机有、模拟器没有的能力是**环境差异**，不是缺陷；两边都没有才是真缺陷。

判据与差异表见 [平台事实 §5](platform-facts.md#5-模拟器-vs-真机差异实测换版本要复核)。

### "复制成功"不是一条证据链，是三段不同的状态（P5）

**已复制到磁盘 / 编辑器已保存并加载 / 真机已验证**——这是三个独立的状态，不能合并成"已同步"。

磁盘复制成功 ≠ 编辑器加载了新代码。**不要承诺"绑定一次以后自动生效"。**

验证要三件事一起做：
1. **回执与校验和**：同步输出是成功结论，且每个目标的字节数/哈希与产物一致；大小或哈希不一致即失败。
2. **构建标记**：脚本内或日志里出现本轮的构建/版本标记行——证明编辑器读到的是**本轮**源码。
3. **每轮重做**：切换或新建关卡会产生新目录、可能仍指向旧脚本。**不要依赖记下来的关卡 id**，每轮试玩前重新同步。

### 先分诊，再修（P12）

每个真机缺陷先建最小复现，然后分类：Lua / 素材 / 布局 / 模拟器差异 / 平台未知。

**不先分诊，就会去修不存在的问题。**

### 用户手改过的脚本要合并回来

实机手改的脚本，先核对并把有效修改**合并回工作区与存档源码**，再进入下一轮——否则下一轮会被旧存档覆盖。

## 准备交付说明

在 `docs/device-handoff.md` 写清**本项目实际需要**的操作：交付文件与版本、资产导入顺序、入口脚本与挂载对象、需要核对的控件/模板、脚本路径、试玩步骤与预期、已知限制与未验证项。

- **GIA 不保存脚本挂载关系，也不保存脚本同步配置**——脚本映射与挂载必须单列。
- 交付清单写成**可逐条执行的步骤**，每条带"预期结果 + 回传格式"。
- **不要把脚本头部注释里的功能直接抄成"已实现"**——先确认该功能真的存在，未做的明确标"未构建"。（源码注释是假设，见 [P6](reasoning-patterns.md#p6--结论即假设)）
- 已有的正确映射与挂载直接复用，只说明本轮新增或变化项。
- **导出文件路径不等于真机已导入。**

## 用户需要做什么

| 环节 | 用户操作 / 回传 | AI 配合 |
|---|---|---|
| 导入与挂载 | 导入本轮资产，核对脚本映射路径，把入口脚本挂到指定控件/容器/模板 | 给"哪个文件 → 哪个挂载对象"的对应关系与本轮变化项 |
| 核对真实索引 | 检查导入后目标控件/模板的实际索引；变化时给资产/控件名与原值 | 按控件身份校准工程与脚本，复用已有回传不重复索取 |
| 绑定更新位置 | 若用脚本同步，确认账号、关卡与导入脚本目录 | 准备路径对应关系、保存配置、预览差异 |
| 更新脚本 | 在「Lua 脚本 → 实机脚本同步」检查源文件、目标路径与差异并确认复制 | 完成源码与索引修复、保存工程，指出新增脚本仍需建立的映射/挂载 |
| 保存与试玩 | 在千星沙箱保存并重新试玩，按清单走开局、成功/失败、重开及本轮变更，回传异常与画面/日志 | 对照预期定位、修复并给下一轮更新与回归步骤 |

绑定同步目录只是便于后续更新的**可选项**。没有本机目录访问能力时，仍可交付 Lua 与明确的手动更新路径——**不以绑定目录作为真机验证前提**。

## 导入后的索引校准

**以真实编辑器的索引为准。**

按当前模拟器接口的 `setControlGuid` / `controlGuidChanges` 流程处理。**用户手工改过、没有生成记录时，仍要按控件身份核对**，不能只看记录是否为空。

1. 按资产与控件身份读变更记录，把连续 A→B→C 解析为**最终**索引。同一 `batchId` 是一批同时映射，**不能逐条替换数字**；**不能把模板索引和运行时控件 `Id` 混用**。
2. 检查存档 `scripts[].source`、路径源码、常量、配置表与身份校验，**按语义**同步到最终索引。非空内联源码优先执行——**不能只改外部 `.lua`**。
3. 复核旧值残留，**保留同值但无关**的图片 ID、脚本映射 ID 等数值。无法判定的引用保留待处理。
4. 仅当相关引用全部同步、或确认无引用后，用最新 revision 调 `acknowledgeControlGuidChanges{changeIds}`。**不清空未处理项。**
5. 请用户保存完整存档，重启试玩并回归创建、身份检查与受影响流程，再做真机验证。

当前版本**没有**控件索引的批量同步/自动替换工具：这条必须**按语义手工做**。不要承诺"一键全量替换"，也不要用全局数字替换。**三方核对（索引记录 / 存档源码 / 工作区 `.lua`）缺一不可。**

## 脚本同步配置

先读存档已有的同步配置；缺少时由 AI 发现候选并**请用户确认**目标账号/关卡。**多个候选不能只按最近修改时间猜选。**

| 配置项 | 含义 |
|---|---|
| `workspaceDir` | 本项目在工作区内的相对目录，如 `workspace/my-game` |
| `clientImportRoot` | 当前账号/关卡实际的 `external_lua_file/default_import_file` **绝对**路径 |
| `clientSubdir` | 保留导入后脚本映射的相对路径，通常与工作区项目目录同值 |

目标文件 = `<clientImportRoot>/<clientSubdir>/<脚本相对路径>`；**保留目录层级，不按文件名平铺**。改动路径后核对真实编辑器的映射是否仍指向它。

这些路径属于**运行模拟器服务的机器**：远程 Web/MCP 不能把浏览器所在电脑的路径当作服务端可访问路径。目录绑定随完整存档保存，**不写入 GIA，也不会建立实时或双向同步**。

### 让 AI 配合更新

AI 可调用 `qxqy_script_sync` 的 `discover/status/configure/preview`：发现目录、读写配置、预览差异。**没有 apply——复制只能由用户在编辑器确认。**

1. **对齐当前版本。** 核对索引变更、工作区源码、存档内联源码与已知的实机手改。非空白内联 `source` 优先，否则读 `path`。发现实机独有修改先比较并合并回项目，有真实冲突再请用户判断。
2. **保存并预览差异。** 先完成引用修复与已核验变更的确认，**请用户在"模拟器"标签点【保存存档】**（复制要求存档已保存且之后未再改动），再预览每个脚本的来源、目标与新增/覆盖内容。**复制前不能说"已同步到真机"**，只能说"已准备更新"。
3. **用户确认复制。** 请用户在「Lua 脚本 → 实机脚本同步」执行"保存存档并查看更新"。**存在未确认的 `controlGuidChanges` 时复制会被直接拒绝。** AI 不调用人工复制端点，不用 shell 或目录联接绕过确认。
4. **核对结果再试玩。** 记录复制回执的成功/失败与备份位置（`<workspace>/.qxqy-script-sync-backups/<planId>/`）。**只同步存档登记的 Lua 脚本**（含未挂载的 require 模块），不是整目录镜像；新增脚本仍须在真实编辑器建立映射和必要挂载。

**已知会被拒绝或失败的情形**（先修掉再重试，不要反复重放）：

| 情形 | 处理 |
|---|---|
| 计划过期（存档/源文件/目标已变） | 重新预览 |
| 存在未确认的 `controlGuidChanges` | 拒绝复制，先处理完 |
| 缺文件、目标重名、路径穿越、目标为符号链接 | 该行报错且不可选 |
| 源文件内容与预览不一致 | 会要求明确选择"用项目文件里的代码" |
| 单个文件非原子 | 失败行单独报告 |

用户选择手动更新时，给本次改动文件与准确目标路径，提醒保留实机已有修改；手改后把最终版本同步回项目。

## 缺陷修复与回归

请用户按交付清单实际试玩，记录：真机环境、操作步骤、期望/实际、截图或日志、可复现性。证据标 `runtime=device` 并注明执行者与来源。

每个缺陷先建最小复现 → 分类 → 先更新用例或明确人工检查 → 修复 → **重复模拟器与真机验证**，保留修复前后证据。
