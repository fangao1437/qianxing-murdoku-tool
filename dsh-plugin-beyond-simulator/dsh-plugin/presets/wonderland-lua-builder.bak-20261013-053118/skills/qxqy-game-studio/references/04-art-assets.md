# 4 美术素材

**什么时候是这一步**：HTML 体验已确认，要上正式美术。

**做完的标志**：每个关键视觉元素都有目标素材/图元、使用位置、还原方式与模拟器替代；未知 ID、预览限制与真机核验项都已标注。

本步骤**不打开模拟器、不改存档**。

---

## 怎么想

### 关键可读性不能只挂在官方图片上

模拟器对素材的预览是**受限的**（范围随版本变化，详见 [平台事实 §2.3](platform-facts.md#23-素材预览范围版本相关先确认再断言)）。官方图片在模拟器里可能只显示缺失框——**那是预览限制，不是素材不可用**。

所以：**每个关键元素都要配一个在模拟器里看得清的替代**（图元拟合、色块 + 文本、几何形状），官方图片作为真机增强。

这条如果留到步骤 6 才发现，整轮返工。

### 分清三层支持度（P14）

**能在编辑器里创建/保存 ≠ Lua 能读写 ≠ 试玩/真机能生效。** 三者互不等价：动画与音效在 2.0.8 是空操作、按键提示不画键位、模板引用控件不会自动展开。

写方案时对每个视觉手段**标明它属于哪一层**，未验证的进真机清单。

### 有真分歧才分叉

真正存在视觉方向分歧时，在**同一布局、同一玩法状态**下给少量可比较的方向让用户选。没有分歧就直接采用推荐方向并说明理由——不要为了流程而制造选择题。

---

## 要产出什么

`docs/art-bible.md`：体验形容词、主/辅/警示色、轮廓与层级规则、角色/道具识别特征、素材来源与用途、目标 `imageSource` + `imageId`/图元、模拟器占位方案、真机核验项。

### 素材事实

- 官方原神/千星素材可以使用。
- `SetImage(imageSource, imageId)` 改图，**两者必须成对匹配**——不匹配同样显示缺失框。
- 缺失框**不能证明**资源不可用：照常选目标 ID，记录 `targetId`，真机核验"图对不对"。九宫格与动效视觉同样留真机。
- 音频：Lua 有播放接口，但模拟器不出声。**音效不是可验证的反馈通道**——必须同时有视觉反馈。

### UI 还原规格

布局字段用千星坐标约定：**原点左下、锚点相对父矩形 0–1**。不写 DOM 选择器、CSS 类或 JS/Lua 函数名。

| 字段 | 含义 |
|---|---|
| `id` / `kind` | 稳定控件名；`kind` 取官方 11 类之一（清单见 [平台事实 §1.1](platform-facts.md#11-控件类型11-类)） |
| `parent` / `anchor` / `offset` / `size` | 控件树与跨画布布局（PC 只做等比放大/留边） |
| `styleToken` / `assetId` | 色板、字号、间距与资产清单引用 |
| `visibleWhen` / `action` | 可见状态与抽象玩家动作 |
| `motionIntent` | 触发、时长、曲线与**可降级方式**（动效在模拟器是空操作，必须给出属性替代） |
| `fallback` | 模拟器看不清时的替代展示 |
| `deviceCheck` | 需要在真机确认的项（真实图片、字号完整、动效） |

**实例化限制会影响控件树设计**：只有**存为模板的客户端控件的父节点**能被动态创建，主屏控件与模板子节点都不行。方案里要写明**哪一层是模板、哪一层是实例**。

### 成本控制

- 只做少量有差异的方向。高成本拼图或帧动画先准备**关键样本**，批量制作随步骤 5 的实现需要推进。
- **先定色板、字号、间距**，再产出素材，避免返工。
- 每个目标 ID 记一行来源与用途；来源未知的标 `[推断]`。
